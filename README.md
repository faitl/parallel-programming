## Выводы

1. **Код полностью переносим.**  
   Исходный MPI-код не потребовал изменений при переносе на суперкомпьютер. Вся адаптация свелась к настройке окружения через `module load` и созданию Slurm-скрипта для отправки задачи в очередь. Это подтверждает одно из главных преимуществ MPI — кроссплатформенность и готовность к работе в распределённых средах.

2. **Масштабирование близко к идеальному.**  
   На выделенных ядрах кластера ускорение растёт почти линейно: при удвоении количества процессов время выполнения сокращается примерно в 2 раза. Для 8 процессов достигнуто ускорение **7.6–8.0×**, что значительно ближе к теоретическому пределу, чем при запуске на локальном ПК. Это объясняется отсутствием конкуренции за память, кэш и системные ресурсы.

3. **Стабильность измерений.**  
   Стандартное отклонение времени между повторными запусками не превышает 0.3 секунды даже для больших матриц. На локальном компьютере разброс мог достигать 10–20% из-за фоновых процессов, тогда как на суперкомпьютере узел изолирован, и замеры воспроизводятся с высокой точностью.

4. **Преимущества HPC-среды проявляются при параллелизме.**  
   Главное достоинство суперкомпьютера — не скорость одного ядра, а возможность запустить десятки или сотни процессов на выделенных ресурсах с высокоскоростной сетью InfiniBand. Для задач, которые можно распараллелить, это даёт кратный выигрыш, недостижимый на настольной системе.

**Итог:** Перенос MPI-программы на суперкомпьютер «Сергей Королёв» подтвердил её готовность к работе в реальных HPC-условиях. Выделенные ресурсы, высокоскоростная сеть и планировщик задач Slurm позволили достичь почти идеального линейного ускорения. Для однопоточных задач современный ноутбук может быть быстрее, но для масштабируемых вычислений кластер остаётся безальтернативным инструментом.
